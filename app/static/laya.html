تصمیم‌گیری روی متن با Jev

Jev یک «موتور تصمیم» است: یک متن یا JSON را می‌خواند و به چند سؤال مشخص جواب می‌دهد (کدام گزینه؟ چقدر؟ بله یا نه؟). جواب‌ها را به‌صورت ساختاریافته برمی‌گرداند. برای سؤال‌های انتخابی، احتمال هر گزینه را هم می‌دهد.

    "state": "We were billed twice. Please refund us.",

      "refund": {"type": "noul",

    }
  }'

استفاده

۱. اولین پیش‌بینی

وضعیت و سؤال‌ها را به سرویس TypeSafe بفرست.

import os
import httpx

state = "Hi, we were billed twice for March. Please refund the duplicate today or we will cancel our plan."
questions = {
    "department": {"type": "choice", "instructions": "Which department should handle this?",
                   "criteria": {"billing": "invoices, payments, refunds",
                                "technical": "bugs, outages, system errors",
                                "other": "everything else"}},
    "urgency":    {"type": "score", "instructions": "How urgent is this?",
                   "criteria": ["not urgent", "soon", "blocking"]},
    "churn_risk": {"type": "noul", "instructions": "Does the user threaten to cancel or leave?"},
}

response = httpx.post(
    "https://api.typesafe.ai/v1/systemone",
    headers={"Authorization": "Bearer " + os.environ["TYPESAFE_API_KEY"]},
    json={"model": "jev-latest", "state": state, "questions": questions},
    timeout=30,
)
response.raise_for_status()
answers = response.json()["answers"]
print(answers["department"]["choice"])
print(answers["department"]["probabilities"])
print(answers["urgency"]["score"])
print(answers["churn_risk"]["noul"])

۲. شکل سؤال‌ها و جواب‌ها

نوعcriteriaفیلدهای جواب
choice{"label": "description", ...}choice برچسب برنده، probabilities احتمال هر برچسب
scoreفهرست سطح‌ها، از پایین به بالا: ["low", "mid", "high"]score امتیاز مورد انتظار (عدد اعشاری)، probabilities برای هر سطح ("0"، "1"، …)
noulاختیاری: {"true": "...", "false": "..."}noul احتمال «بله» (۰ تا ۱)

پاسخ‌های choice و score فیلد confidence دارند. مقدار noul احتمال پاسخ «بله» است.

۳. فارسی و زبان‌های دیگر

می‌توان متن فارسی را در آزمایشگاه وارد کرد. برای مقایسه، همان متن را به انگلیسی هم امتحان کن و پاسخ‌ها را با نمونه‌های مورد انتظار بسنج.

۴. چند سؤال در یک درخواست

برای چند سؤال درباره‌ی یک متن، همه را در questions بفرست. برای متن‌های مستقل، هر متن درخواست جداگانه‌ای دارد. شهر هر جمله‌ی تازه را یک بار می‌پرسد و نتیجه را نگه می‌دارد.

۵. استفاده از جواب در پایتون

department = answers["department"]["choice"]
urgency = answers["urgency"]["score"]
needs_review = answers["department"]["confidence"] < 0.6

آستانه‌ی اطمینان را روی نمونه‌های خودت ارزیابی کن. مقدار ۰٫۶ در این مثال فقط نمونه است.

۶. از خط فرمان

در آزمایشگاه روی HTTP بزن و دستور curl همان درخواست را کپی کن. دستور، کلید را از TYPESAFE_API_KEY می‌خواند.

۷. مسیر API همین پروژه

آزمایشگاه از POST /api/jev/predict استفاده می‌کند. بدنه‌ی درخواست شامل state و questions است. مسیر GET /api/status وضعیت Jev را نشان می‌دهد.

نکات عملی

همین نکته‌ها در سؤال‌های شبیه‌ساز چراغ هم به کار رفته‌اند.

متن را کوتاه و متمرکز نگه دار

اطلاعات مربوط به مسئله را در state بگذار. شبیه‌ساز برای هر چهارراه یک جمله‌ی مستقل می‌فرستد.

مقایسه را صریح بنویس

شبیه‌ساز اعداد حسگر را خلاصه می‌کند و در جمله می‌گوید کدام مسیر شلوغ‌تر است.

قانون را در instructions بنویس

مثلاً an ambulance always gets green first در سؤال مربوط به چراغ آمده است.

پاسخ‌ها را کش کن

شبیه‌ساز برای متن تکراری، پاسخ قبلی را از حافظه می‌گیرد. این کار زمان و تعداد درخواست‌ها را کم می‌کند.

گزینه‌ها را توصیف کن

در choice برای هر گزینه توضیح کوتاهی بنویس، مثل "billing": "invoices, payments, refunds".

نتیجه را با نمونه‌های واقعی بسنج
